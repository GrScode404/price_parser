# Price Parser

Асинхронный парсер цен товаров с сохранением результатов в Redis.

Проект предназначен для периодического получения актуальных цен по списку URL. При ошибке получения или обработки товара его предыдущее значение в Redis сохраняется.

## Возможности

* асинхронная обработка товаров;
* ограничение количества одновременных HTTP-запросов;
* повторные попытки при временных HTTP-ошибках и сетевых сбоях;
* извлечение цены из JSON на странице товара;
* сохранение актуальных цен в Redis;
* защита старого значения от затирания при ошибке парсинга;
* запуск в Docker;
* Redis запускается отдельным контейнером;
* периодический запуск парсера через Linux `cron`;
* автоматические тесты.

## Архитектура

```text
                         каждые 15 минут
Linux cron ─────────────────────────────────┐
                                            │
                                            ▼
                                  price-parser container
                                            │
                               ┌────────────┴────────────┐
                               │                         │
                          HTTP-запросы               RedisStorage
                               │                         │
                               ▼                         ▼
                        Страницы товаров              Redis
```

Парсер является одноразовым процессом:

1. запускается;
2. загружает список URL;
3. обрабатывает товары;
4. сохраняет успешно полученные цены;
5. завершает работу.

Периодичность запусков обеспечивает внешний планировщик `cron`.

## Логика обработки

URL товаров находятся в файле `products.txt`.

Для каждого товара:

```text
URL
 ↓
HTTP-запрос
 ↓
получение страницы
 ↓
извлечение JSON
 ↓
проверка цены
 ↓
сохранение в Redis
```

Если на любом этапе происходит ошибка, значение в Redis не изменяется.

Например, если:

```text
product:42 = 27.42
```

и следующий запуск не смог получить цену товара №42, значение `27.42` останется в Redis.

## Redis

Для каждого товара используется отдельный ключ:

```text
product:<id>
```

Например:

```text
product:1
product:42
product:100
```

Значение ключа — текущая цена товара.

История изменения цен не хранится.

## Повторные запросы

Для временных ошибок используются повторные попытки.

Повтор выполняется при:

* HTTP `429`;
* HTTP `500`;
* HTTP `502`;
* HTTP `503`;
* HTTP `504`;
* сетевых ошибках;
* таймаутах.

Количество попыток:

```text
3
```

Интервал между попытками увеличивается экспоненциально:

```text
1 секунда
2 секунды
4 секунды
```

Если сервер передал заголовок `Retry-After`, его значение используется для ожидания перед повторным запросом.

## Ограничение параллелизма

Для ограничения количества одновременных HTTP-запросов используется `asyncio.Semaphore`.

Текущее ограничение:

```text
10 одновременных запросов
```

Таким образом, приложение не отправляет все 100 запросов одновременно.

## Локальный запуск

Создать виртуальное окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Установить зависимости:

```bash
pip install -r requirements.txt
```

Запустить Redis.

Затем:

```bash
make run
```

По умолчанию приложение подключается к:

```text
REDIS_HOST=localhost
REDIS_PORT=6379
```

Переменные можно изменить:

```bash
REDIS_HOST=localhost REDIS_PORT=6379 make run
```

## Запуск через Docker Compose

Собрать и запустить Redis:

```bash
docker compose up -d redis
```

Запустить парсер:

```bash
docker compose run --rm price-parser
```

Парсер подключается к Redis по имени Docker Compose-сервиса:

```text
REDIS_HOST=redis
```

Redis и парсер работают в общей Docker Compose сети.

После завершения парсер останавливается. Это нормальное поведение: контейнер выполняет одну задачу и завершается.

## Cron

Парсер запускается каждые 15 минут через Linux `cron`.

Текущее расписание:

```cron
*/15 * * * * cd /home/bakunin_misha/projects/price_parser && /usr/bin/docker compose run --rm price-parser >> /home/bakunin_misha/projects/price_parser/cron.log 2>&1
```

Расшифровка:

```text
*/15 * * * *
│
└── запуск каждые 15 минут
```

Cron запускает одноразовый контейнер парсера:

```bash
docker compose run --rm price-parser
```

После завершения контейнер автоматически удаляется благодаря `--rm`.

Логи запуска сохраняются в:

```text
cron.log
```

Файл лога не отслеживается Git и не попадает в Docker build context.

## Тесты

Запуск тестов:

```bash
make test
```

Тесты проверяют:

* загрузку URL;
* успешное получение страницы;
* retry при временных ошибках;
* обработку HTTP-ошибок;
* корректность извлечения цены;
* обработку некорректных данных;
* успешное сохранение цены;
* отсутствие сохранения при ошибке обработки.

## Результат проверки

Проект проверен на реальном Redis.

Текущий запуск обрабатывает:

```text
100 товаров
100 успешных
0 ошибок
```

Redis содержит по одному ключу на каждый обработанный товар.

## Переменные окружения

| Переменная   | Значение по умолчанию | Назначение |
| ------------ | --------------------- | ---------- |
| `REDIS_HOST` | `localhost`           | Хост Redis |
| `REDIS_PORT` | `6379`                | Порт Redis |

В Docker Compose `REDIS_HOST` устанавливается в:

```text
redis
```

поскольку контейнеры обращаются друг к другу по имени сервиса.
